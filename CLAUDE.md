# CLAUDE.md

Рабочие заметки по проекту для Claude Code и для людей в команде. Файл подхватывается автоматически в начале каждой сессии.

## Что за проект

Кейс Космохакатона (Ростов) — веб-сервис мониторинга NDVI сельхозполей. Две задачи:

1. **Восстановление пропусков.** Заполнить скрытые `primary_ndvi` в тестовом наборе. Автометрика GapScore = round(30·max(0, 1 − RMSE/0.10), 2); RMSE ≥ 0.10 даёт 0 баллов.
2. **Аномалии.** Найти и объяснить аномальные эпизоды в динамике NDVI. Оценивают эксперты.

ТЗ и критерии разобраны в `docs/01…07`. Критерий жюри: комментарии в коде **на русском языке**, непустой README с запуском без обращения к команде.

## Неочевидное про данные

- `private_features.csv` из ТЗ — это `data/test_features_new.csv` (вторая версия, по ней метрика); `data/test_dataset.csv` — первая
  версия, больше не оценивается (см. `docs/03-data.md`). В новой версии нет колонок `ndvi_climatology_*`, у 6 из 20 полигонов нет ERA5.
- **Координат полей в данных нет**, только анонимные `AOI-xxxx`. Контуры из OSM/WorldCereal не с чем связать; карта в сервисе — для новых территорий.
- `primary_ndvi` = coalesce(S2 → Landsat → MODIS). Сенсоры смещены: Landsat +0.037, MODIS +0.083 к S2. Сенсор скрытой точки угадывается по расписанию съёмки (MODIS на сетке doy 97, 113, …, шаг 16; S2 шаг 5; Landsat шаг 8) — правило в `eda/cycles.py` даёт 92 %.
- Baseline «среднее соседей» RMSE 0.093 (GapScore 2.0); глобальная сенсорная коррекция без обучения — 0.084 (GapScore 4.9); потолок при идеальной коррекции около 0.065. Ошибка не зависит от расстояния до соседа, 4.5 % крупных промахов дают 40 % всей ошибки.
- Z-score в данных зависит от сенсора (S2 −0.23, MODIS +0.52): перед детекцией аномалий сенсоры гармонизировать, 31 % «аномальных» точек — одиночные выбросы.
- 10 полигонов train и 23 test без ежедневной сетки и **без ERA5 вовсе**. У 29 train-полигонов с погодой всего 22 ряда ERA5 (соседи в одной ячейке).
- Новые полигоны test: 12 с полной ежедневной историей 2010–2025, 7 с историей без сетки, 20 только сезон 2025.
- `crop_type` статичен и не отражает севооборот. 2020 и 2024 — засушливые сезоны, готовые кейсы для демо.
- Валидация: group-split по полигонам плюс сезон целиком вне обучения; синтетические пропуски маскировать так же, как в test (все динамические колонки).

## Окружение

Всё через **uv** (`uv run`, `uv add`, `uv sync`), Python 3.14 (`.python-version`), зависимости в `pyproject.toml` + `uv.lock`. Никаких `pip`/`python` напрямую.

```bash
uv sync                          # базовые зависимости + dev
uv run python -m eda.run_all     # полный EDA (~30 с)
uv sync --group ml               # бустинги, whittaker-eilers, optuna, shap
uv sync --group geo              # STAC, rasterio, xarray, geopandas, Open-Meteo, osmnx
UV_TORCH_BACKEND=cu130 uv sync --group dl   # torch (CUDA 13.0 для RTX 5070), PyPOTS, pygrinder, chronos
uv sync --group torch            # только torch (по умолчанию CPU-сборка) — хватает для инференса из models/
uv sync --group serve            # только веб-слой: FastAPI, uvicorn, plotly, duckdb (эта группа идёт в образ)
uv sync --group service          # всё для запуска сервиса на разработке: serve + geo + infer + ml
uv sync --group agent            # pydantic-ai, anthropic, mcp
uv sync --group openeo           # отдельно: конфликтует с geo по xarray
```

Версии актуальны на сентябрь 2026, все пакеты имеют wheels под 3.14. Новые библиотеки сверять через Context7 и PyPI перед добавлением.

На Windows кириллица в stdout: запускать с `PYTHONIOENCODING=utf-8`. Файлы писать только с `encoding="utf-8"`.

Локальный просмотр HTML через `file://` в MCP-браузере запрещён — поднимать `uv run python -m http.server` и открывать `http://127.0.0.1:PORT/...`.

## Правила репозитория

- Ветка одна — `main`. Рабочие ветки короткоживущие, вливать через merge, не оставлять.
- Код: модули с функциями до 50 строк, файлы до 400 строк, без мутаций входных DataFrame, русские комментарии и docstring, пути от `Path(__file__)` или из `eda/config.py`.
- Артефакты анализа (графики, summary.json) коммитятся, чтобы отчёт читался без запуска; крупные промежуточные файлы — нет.

## Стиль работы

- В репозитории (README, отчёты) — полно и технически.
- В чате — коротко, без жаргона, термины через бытовые аналогии: команда смешанная, не все из data science.
- Задачи ставятся широко («сделай всё, что можешь») — не ждать уточнений, делать максимум и показывать результат.
