# Мониторинг вегетационной динамики сельхозполей (Космохакатон, Ростов)

Веб-сервис, который по контуру поля — выбранному на карте или нарисованному вручную —
сам собирает спутниковые и метеоданные, восстанавливает пропуски во временном ряде NDVI
и находит периоды, когда растительность развивалась хуже обычного, с объяснением причины.

Решает обе задачи кейса:

1. **Восстановление пропусков `primary_ndvi`.** RMSE **0.0716** на честной валидации
   против **0.0911** у baseline организаторов (порог метрики — 0.10).
   GapScore ≈ 8.5 против 2.7.
2. **Детекция и интерпретация аномалий.** 285 эпизодов на 39 полях за 15 лет,
   43 % ложных срабатываний отсеиваются, каждый эпизод сопровождается объяснением
   на русском языке и оценкой уверенности.

## Быстрый старт

```bash
# окружение
uv venv .venv --python 3.12
uv pip install --python .venv/bin/python -e ".[web]"

# обучение модели восстановления пропусков (~15 с)
.venv/bin/python scripts/train.py

# batch-инференс: test_dataset.csv -> submission.csv
.venv/bin/python scripts/predict.py

# веб-сервис на http://127.0.0.1:8000
.venv/bin/python -m uvicorn ndvi.service.app:app --port 8000 --app-dir src
```

Через Docker:

```bash
docker compose up --build      # сервис на http://127.0.0.1:8000
```

Внешние ключи и переменные окружения **не нужны**: все источники данных открытые.

уникальность пар «полигон + дата», отсутствие `NaN`, формат даты, диапазон значений.

## Как устроено решение

### Задача 1: восстановление пропусков

Ключевое наблюдение: `primary_ndvi` — это не один ряд, а склейка трёх спутников
(`coalesce(Sentinel-2 → Landsat → MODIS)`), и они систематически расходятся: Landsat
читает на +0.037 выше Sentinel-2, MODIS — на +0.078. Поэтому «среднее двух соседей»
ошибается системно, когда сенсор скрытой точки отличается от сенсоров соседей.

Пайплайн:

1. Все наблюдения приводятся к шкале Sentinel-2.
2. Сенсор скрытой точки угадывается по расписанию съёмки (MODIS — дни года кратные 16
   с остатком 1, Landsat — шаг 8 дней, Sentinel-2 — шаг 5). Точность 81 %.
3. Строится опорный прогноз: интерполяция соседей в единой шкале + смещение угаданного сенсора.
4. Градиентный бустинг предсказывает **поправку** к этой опоре по ~60 признакам:
   до трёх соседей с каждой стороны, робастно сглаженная кривая сезона, климатическая
   норма поля, накопленные осадки и жара, длина цепочки пропусков, культура.

Подробности, таблицы экспериментов и разрезы качества — в
[`reports/experiments.md`](reports/experiments.md) и
[`reports/research_report.md`](reports/research_report.md).

### Задача 2: аномалии

1. Гармонизация сенсоров и пересчёт нормы по гармонизированному ряду — иначе z-score
   показывает, каким спутником снимали, а не состояние поля (средний z: MODIS +0.52,
   Sentinel-2 −0.23 в исходных данных, +0.08 и +0.04 после гармонизации).
2. Эпизодом считается только устойчивое отклонение: три и более наблюдений подряд ниже
   нормы **и** просевшая сглаженная кривая сезона. Отсеивает 43 % срабатываний.
3. Падение NDVI после пика сезона у зерновых помечается как уборка, осенний спад у
   озимых — как сев и всходы, а не как гибель посева.
4. Каждый эпизод сопоставляется с погодой: осадки и число жарких дней за 30–60 дней до
   эпизода сравниваются с нормой того же окна в другие годы.

### Автосбор данных

| Данные | Источник | Ключ |
|---|---|---|
| Sentinel-2 L2A | STAC Earth Search (AWS Open Data), COG + маска облаков SCL | не нужен |
| Landsat 8/9 L2 | STAC Microsoft Planetary Computer, маска QA_PIXEL | не нужен |
| MODIS MOD13Q1 | REST-сервис ORNL DAAC | не нужен |
| Погода | Архив ERA5-Land через Open-Meteo | не нужен |
| Контуры полей | OpenStreetMap Overpass, `landuse=farmland` | не нужен |
| Поиск региона | OpenStreetMap Nominatim | не нужен |

Google Earth Engine рассматривался как основной вариант, но требует аккаунт Google Cloud
и интерактивную авторизацию, поэтому реализован путь на открытых каталогах.

Каждый источник изолирован: недоступность одного не ломает ответ, интерфейс показывает,
какие источники отработали и сколько наблюдений дали. Всё скачанное кэшируется на диск,
повторный запрос по тому же полигону отвечает мгновенно.

### Обучающие и проверяемые поля на карте

Каждое поле помечается ролью: **обучение**, **предсказание** или **и то и другое**. Роль
задаёт цвет контура на карте (зелёный / фиолетовый / жёлтый), хранится вместе с полигоном
и меняется двойным щелчком по полю в списке (`PATCH /api/polygons/{id}/role`).

Роль не декоративная. Ряды полей с ролью «обучение» попадают в общий коридор нормы: у свежего
полигона своей истории нет, и норма достраивается по эталонным полям той же культуры. Это ровно
проблема «холодного старта» из данных соревнования, где часть тестовых полей представлена
одним сезоном. В карточке результата показано, сколько эталонных полей участвовало в норме.

Кнопка **«Собрать демо-набор полей»** (`POST /api/demo/seed`) берёт девять настоящих полей
под Зерноградом из OpenStreetMap и раскладывает их на шесть эталонных и три проверяемых —
чтобы разделение было видно на карте сразу.

Для датасета соревнования роли расставлены автоматически: 39 полигонов есть и в `train`,
и в `test` (обучение и предсказание), ещё 39 встречаются только в `test` (только предсказание).
Это видно списком на вкладке «Демо на датасете».

### Почему полей датасета нет на карте

Координат в данных нет — только анонимные `AOI-xxxx`. Мы попробовали восстановить положение
по погодному отпечатку: суточный ряд ERA5 — это география, последовательность дождей за сезон
почти уникальна для места. `scripts/locate_polygons.py` берёт сетку точек по области, скачивает
для каждой архив ERA5 и ищет узел с лучшим совпадением. Локализовалось 55 полигонов из 78,
все — в Ростовской области.

Но точность оказалась грубой, и мы её измерили, а не оценили на глаз: положение каждого поля
считалось дважды, по двум непересекающимся половинам сезона 2025. Две независимые оценки
расходятся в среднем на **61 км** (у случайных пар точек в этой области — 257 км). Сигнал
настоящий, но собственная ошибка около 60 км.

Рисовать по таким числам контуры полей было бы обманом, поэтому на карте их нет. Разделение
полей датасета на обучающие и тестовые видно списком на вкладке «Демо на датасете».

### Адаптивность к регионам

Ни модель, ни детектор не привязаны к Ростовской области: норма считается из собственной
истории поля, смещения сенсоров оцениваются по его же наблюдениям, погода берётся по его
координатам. Проверка на удалённых регионах — `scripts/check_regions.py`, результаты
в [`reports/research_report.md`](reports/research_report.md).

## Ограничения

- В данных соревнования нет координат полей (только анонимные `AOI-xxxx`). Положение
  восстанавливается по погодному отпечатку с точностью около 60 км — это район, а не контур,
  поэтому контуры полей датасета на карте не рисуются.
- Выбросы в скрытых точках теста (облачные провалы) принципиально не восстанавливаются:
  4 % таких точек дают 41 % всей ошибки.
- Первый сбор данных по новому полю занимает от 20 секунд до минуты на несколько сезонов;
  дальше работает кэш.
