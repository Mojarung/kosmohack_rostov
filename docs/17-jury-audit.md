## Раздел 0. Метрика (0–30)

Есть: финальная модель exp-008, `submission.csv` в корне, формат проверен (2 323 строки, ровно одна на пару
`anon_polygon_id + date`, дат формата `YYYY-MM-DD`, без `NaN`), инференс без обучения из `models/improved/`.

Риск: `submission.csv` использует калибровку историческими агрегатами (mean/std) из первой версии test.
Это данные, опубликованные организаторами, но они несут информацию о скрытых значениях второй версии.
Без калибровки тот же ансамбль даёт 0.0553 → GapScore 13.41 (`submission_model.csv`). Решение — за командой,
вопрос вынесен в [docs/15](15-consultation-questions.md) и в чек-лист.

Потолок задачи: усечённый RMSE 0.046 при физическом пределе 0.041 (шум одного наблюдения). Дальше растить
метрику нечем — ошибку определяют 1.2 % выбросов в самих ответах.

## Раздел 1. Презентация MVP (0–15)

Было: не начата — гарантированный ноль по «ясности» и слабая опора для «демонстрации».
Стало: `presentation/index.html` — 14 слайдов, палитра и типографика те же, что в интерфейсе, текст короткими
блоками, все числа из `reports/`. Печать в PDF — клавиша `P`.

Остаётся за командой: прогон выступления, живое демо основного пользовательского пути (карта → контур → сбор →
сезон → вывод), готовность отвечать по происхождению данных и экспериментам (ответы — docs/14, docs/15).

## Раздел 2. Работа с аномалиями и регионами (0–27)

- **Детекция (0–7).** Гармонизация сенсоров, норма по истории поля, эпизоды по устойчивости и силе, семь классов
  причин с аргументами из ERA5, фенологии, регионального контекста и NDWI. Нетривиальные случаи разделены:
  «не засеяно» и «севооборот» не путаются с угнетением. Проверка без разметки: precision 0.70, полнота по
  критическим 0.73, зависимость от сенсора снята (corr 0.05 против 0.18).
- **Управление полигонами (0–5).** Добавление, открытие без пересбора, удаление, поиск готовых контуров OSM,
  рисование произвольного полигона, цвет контура по тяжести. Минус: источник готовых контуров один.
- **Автосбор (0–5).** Пять источников, ни одного ключа, каждый источник изолирован, три зеркала Overpass,
  параллельный сбор (6 сезонов ≈ 2 мин 49 с), прогресс по шагам.
- **Адаптивность (0–5).** Каталоги глобальные, норма считается из истории самого поля, привязки к региону нет.
  Ограничение: норме нужно ≥ 3 лет истории.
- **Дополнительные идеи (0–5).** «Шум дня» соседних полей как признак, определение сенсора по расписанию съёмки,
  простой язык для фермера, погодные показатели (осадки за 30 дней, тепло, сухой период), карты NDVI/NDMI,
  агент с вопросами про поле в свободной форме (`POST /api/ask`, без ключа — разбор по правилам),
  MCP-сервер с шестью инструментами и печатный HTML-отчёт по полю (`GET /api/report/{pid}`).

## Раздел 3. Отчёт и исследование (0–10)

Baseline описан с числами и ограничениями, из них выведены шесть гипотез, каждая проверена; журнал
`experiments/` фиксирует условия (маски, сплиты, seeds) и результаты, включая отрицательные (Optuna, CatBoost,
Chronos-2, шум входа). Отчёт [docs/14](14-research-report.md) доведён до финальной конфигурации exp-008.

## Раздел 4. Качество кода и документация (0–8)

Есть: русские комментарии и docstring, файлы до 400 строк и функции до 50, конфиги в `*/config.py`, тесты,
`pyproject.toml` + `uv.lock`, Dockerfile и docker-compose, README со стеком, структурой и всеми командами.

Слабые места, которые видит эксперт:
1. в пакете `gapfill/` двадцать модулей с префиксом `research_` — часть из них участвует в продовом
   инференсе (`predict_improved` импортирует `research_*`), и по имени это не читается;
2. README большой: эксперту нужен короткий путь «поставил — запустил — проверил» в первом экране;
3. три файла `submission*.csv` в корне — надо явно сказать, какой из них конкурсный (сказано в README).

## Раздел 5. Удобство использования (0–10)

Пять экранов, один экран без прокрутки страницы, интерактивные графики с общим окном просмотра и курсором,
карта со спутниковой подложкой и поиском мест, «светофор» и три вопроса простым языком, «Мои поля».
Дополнительная ценность: погодные показатели, снимки поля, дашборд EDA, batch-режим для технической проверки.

## Разбор внешней критики (2026-09-05, вечер)

Команда прогнала решение через сторонних критиков. Что подтвердилось и что сделано:

| Замечание | Проверка | Итог |
|---|---|---|
| «Засухи» при осадках выше нормы (33 эпизода) | подтвердилось: сухая серия ≥ 20 дней была самостоятельным признаком | исправлено, стало 13 (все по жаре) — [exp-106](../experiments/exp-106-detector-false-drought.md) |
| Пропущена треть сезонов с угнетением | подтвердилось: сезон целиком чуть ниже нормы не проходил ни один порог | добавлена ветка «долгий эпизод», полнота 0.51 → 0.60 |
| Фенологический довод весны в осенних эпизодах | подтвердилось | ветка «ранний спад» ограничена главным сезоном |
| Один тяжёлый полигон роняет сбор для всех | подтвердилось: `ProcessPoolExecutor` не пересоздавался | пул сбрасывается, ответ 503 с причиной; добавлен предел площади 50 000 га |
| README учит воспроизводить не ту модель, что сдана | подтвердилось | добавлены команды обучения exp-008, `--no-calibration` для чужого файла, seed и гиперпараметры |
| Нет конфига ruff, 131 предупреждение | подтвердилось | конфиг в `pyproject.toml`, автофиксы применены, осталось 22 косметических |
| В сданном файле «физически невозможный» NDVI 2.03 | **не подтвердилось** | в данных кейса есть истинные значения до 1.84 и −2.13; обрезка проверена и ухудшает метрику (16.88 → 16.80), значения оставлены |
| Не решено, какой submission сдавать | справедливо | выбран `submission.csv`, запасной `submission_model.csv` готов |
| Обратный севооборот, константная уверенность, южное полушарие, gapfill не применяется к новому полю | подтвердилось | не сделано, вынесено в ограничения |
