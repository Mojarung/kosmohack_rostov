Дата: 2026-09-04. Сравнивались ветки `eda-report` (модульный EDA, uv-проект) и `eda/data-analysis` (скрипты первого прохода, дашборд). ## Решение

За основу взята `eda-report`. Из `eda/data-analysis` в `main` перенесено:

- **Находки** — все шесть уникальных встроены в модули с воспроизводимыми числами: `sensor_aware` и `sensor_aware_oracle` в `eda/baseline.py` (0.0838 / 0.0824), концентрация ошибки там же, Z-score по сенсорам и годовая погода в `eda/anomalies.py`, общие ряды ERA5 в `eda/coverage.py`, разбиение новых полигонов — в отчёте `08`.
- **Дашборд** — `reports/dashboard/template.html` и собранный `dashboard.html`; сборка заскриптована в `eda/v1/build_dashboard_data.py` (UTF-8, подстановка `__DATA__`, полноценный HTML-каркас), промежуточный JSON не хранится.
- **Скрипты** — сохранены как `eda/v1/` с README, запускаются из окружения проекта (`uv run python eda/v1/…`), пути исправлены.
- **Заметки** — `data/README.md` перенесён в `docs/11-eda-v1-notes.md` с тремя уточнениями прямо в тексте.
- **`CLAUDE.md`** — взят и переписан под объединённое состояние: uv-окружение, Python 3.14, факты из обеих веток, правило «одна ветка main».

Не перенесено: `dashboard_data.json` (генерируется), инструкции окружения через `uv pip install` и `.venv/bin/python` (противоречат правилам проекта), дублирующие `.gitignore` и правки README (взяты из `eda-report`).

После слияния ветки `eda-report` и `eda/data-analysis` удалены, осталась одна `main`.

## Что это меняет в плане моделирования

Практическая проверка сенсорной коррекции закрывает вопрос «стоит ли»: без обучения RMSE падает с 0.093 до 0.084 (GapScore с 2.0 до 4.9), а с истинным сенсором до 0.082. Дальше выигрыш дают смещения по месяцу и полигону, подавление одиночных выбросов у соседей (4.5 % промахов = 40 % ошибки) и бустинг на признаках соседей. Для аномалий обязательна гармонизация сенсоров до расчёта Z-score, иначе четверть точек S2 выглядят угнетением.
