## Что делаем на хакатоне

Нужен веб-сервис мониторинга сельхозполей: выбор готового либо собственного контура, автоматический сбор
спутниковых и погодных данных, восстановление NDVI, поиск аномальных периодов и объяснение возможных причин.
Пропуски — только одна часть продукта: автоматическая метрика даёт максимум 30 баллов, остальные 70 —
экспертная оценка функциональности, презентации, исследования, кода и удобства.

В этом запуске меняется только восстановление пропусков. Интерфейс, сбор данных, детектор аномалий,
исходные модели и исходный `submission.csv` не заменяются. Источники постановки:
[задача](01-task-statement.md), [критерии](06-evaluation-criteria.md).

## Какая именно ошибка

NDVI — само восстанавливаемое значение. Уменьшаем **RMSE**: корень из средней квадратичной ошибки
между восстановленным и исходным `primary_ndvi`. Крупные промахи здесь особенно дороги.
Баллы: `GapScore = round(30 × max(0, 1 − RMSE / 0.10), 2)`.

RMSE 0.05 соответствует 15 баллам, 0.01 — 27 баллам. Достижение 0.01 пока не показано.
Значения вне физического диапазона встречаются в исходных метках; удалять их из оценки нельзя.
«Усечённый RMSE» из ранних исследований — только диагностика, не конкурсная метрика и не доказанный предел.

## Как обучалась прежняя модель

Это обучение с учителем на известных значениях NDVI, а не обучение языковой модели другой языковой моделью.
Из видимых дат случайно скрывается 15%; модель получает соседние наблюдения и пытается восстановить скрытое.
Маски повторяются, чтобы из небольшого набора получить разные задачи восстановления.

- **LightGBM:** ансамбль деревьев, 243 признака — циклы спутников, соседи, сглаженные кривые,
  сезонная история, погода, наблюдения других полей в тот же день. Квадратичная функция потерь;
  обучающие метки ограничивались диапазоном −0.1…1.0, контрольные метки не обрезались.
- **SeasonNet:** свёрточные остаточные блоки и Transformer на ежедневной сетке сезона.
  Обучалась с нуля на тех же известных точках и повторном маскировании.
- Финальный прежний прогноз: равные веса LightGBM и SeasonNet, несколько случайных инициализаций
  (3 бустинга и 5 нейросетей). Известные точки test использовались как доступный контекст и обучающие примеры.
- В прошлых экспериментах были CatBoost и Chronos-2. Chronos-2 без дообучения дал RMSE 0.0876
  и нулевой полезный вес в смеси; TabPFN не был запущен. Это не модели-учителя финальной сети.
- Claude используется отдельно для текста объяснений аномалий при наличии ключа, не для предсказания NDVI.

Исторический exp-007 сообщил RMSE смеси 0.0541, на страте новых полигонов с историей — 0.0557.
Эта страта содержит 39 полигонов и не совпадает с текущими 20 полигонами конкурсного файла.
Источники: [описание модели](12-gapfill-model.md), [exp-006](../experiments/exp-006-second-mask-pretrained.md),
[exp-007](../experiments/exp-007-dataset-v2.md).

## Что изменено

1. Для отложенных строк скрываются все динамические колонки, включая погоду. В исходном табличном
   протоколе погода скрывалась не полностью; новая оценка воспроизводит доступность реального test.
2. Используются все сенсорные наблюдения. Вторичный Landsat/MODIS не выбрасывается, если в этот же день
   основным сенсором был Sentinel-2. Добавлены собственные кривые, соседи и расстояния каждого сенсора.
3. Усилен перенос между полями: отношения кривых и остаточных ошибок, похожие поля-доноры,
   условная оценка общего шума по ковариациям полей. Координат анонимных полей нет; это связи по истории,
   а не утверждение об их географическом соседстве.
4. **ResidualSeasonNet** предсказывает поправки к трём сенсорным интерполяциям и вероятности сенсора.
   47 входных каналов, 96 скрытых, 8 свёрточных блоков, один Transformer, dropout 0.25;
   MSE плюс вспомогательная классификация сенсора с весом 0.003. AdamW, lr 0.001,
   weight decay 0.0003, cosine schedule на 400 эпох. На разработочной маске выбрана эпоха 260;
   на подтверждающей маске она зафиксирована заранее.
5. Независимые ошибки деревьев и нейросети уменьшаются смешиванием: 0.6 дерева + 0.4 сеть.
6. Отдельно исследована калибровка опубликованными историческими агрегатами — важное ограничение ниже.

### Добавление условных ковариаций полей

С 427 признаками (вместо 375) и прежними весами 0.6/0.4 получено:

| Вариант | Все точки, 777 | Текущие 20 полигонов, 777 | Все точки, 999 | Текущие 20 полигонов, 999 |
|---|---:|---:|---:|---:|
| Только ML | 0.052529 | 0.056954 | 0.050816 | 0.053385 |
| ML + прежняя калибровка | 0.050602 | 0.048029 | 0.048651 | 0.043214 |

На первой маске калибровка помогает 19 из 20 полигонов. У оставшегося поля значительный скрытый выброс
неоднозначно распределяется между годами. Поэтому дополнительно исследуется устойчивое условное среднее
по известным суммам, а не только нормальная линейная проекция.

Для реальных 2 323 пропусков (без искусственного holdout) структура опубликованных ограничений такова:
363 значения однозначно определяются суммами; 278 входят в однозначно определённые пары; 488 — в большие
группы с известной суммой и суммой квадратов; ещё 1 194 требуют совместного восстановления.
Это описание доступной информации, **не измеренная точность** закрытого test.

### Устойчивое условное среднее

Для неоднозначных сумм нормальная проекция заменена условным средним с ошибками Student-t (df=3).
Использовано представление через гамма-смесь нормальных распределений: каждая выборка точно соблюдает
линейные ограничения. Симметричные отражения помогают перемещать большие остатки между допустимыми датами.
После этого применяются прежние правила однозначных групп и их сумм квадратов.

Зафиксировано 64 цепи, 300 шагов разогрева и 2 500 учитываемых шагов, 8 предложений отражения на шаг,
random seed 42. Усредняются условные нормальные средние. Это численная аппроксимация;
малый разброс цепей не доказывает полную сходимость во всех многомодальных случаях.

| Маска | RMSE всех контрольных точек | RMSE текущих 20 полигонов | GapScore целевого среза |
|---|---:|---:|---:|
| 777, разработка | 0.050162 | **0.045802** | 16.26 |
| 999, подтверждение | 0.048460 | **0.042223** | 17.33 |
| 2026, дополнительный контроль | 0.049099 | **0.043179** | 17.05 |

Увеличение перебора с 32 цепей / 1 500 шагов (0.046011 и 0.042632) сохранило улучшение обоих срезов.
Контрольные ответы и прогнозы для пересчёта:
[`reports/gapfill/improvement/`](../reports/gapfill/improvement/).
Третья маска 2026 проверена с уже зафиксированными настройками: 2 011 контрольных точек целевого среза.
Без калибровки на ней RMSE 0.055460 (все точки — 0.051725), с прежней калибровкой — 0.045273.
Таким образом, выбранная устойчивая поправка улучшила все три разбиения.

## Почему калибровку надо рассматривать отдельно

Старая версия данных содержит у текущих 20 полигонов за 2025 год исторические среднее и стандартное
отклонение NDVI. Они рассчитаны по **другим годам**, в окне ±8 дней по дню года, со стандартным
отклонением `ddof=0`. В их расчёт вошли значения 2010–2024, которые в новой версии скрыты.

Формула проверена на 14 431 полностью известных окнах: средние совпали до 4.03e-16,
суммы квадратов — до порядка 3e-14. Это информация о скрытых ответах в опубликованных признаках,
а не способность модели предсказывать непредсказуемый шум.

Из агрегатов получаются ограничения `A x = b` и `A x² = c`: известные значения вычитаются,
оставшиеся неизвестные нужно распределить между годами. Однозначные значения восстанавливаются точно.
Если разные годы неразличимы по агрегатам, используется усреднение допустимых решений с опорой на
ML-прогноз и распределение ошибок с тяжёлыми хвостами. Неопределённость каждой точки оценивается
отдельным LightGBM на ошибках внутреннего holdout, без внешних контрольных ответов.

Жёстко подогнать все суммы квадратов оказалось вредно: алгоритм может назначить большой выброс
неверному году. Среднее по допустимым вариантам может не удовлетворять условию на квадрат **среднего** —
это нормально: средний квадрат и квадрат среднего различаются. Для RMSE нужен именно условный средний ответ.

Калибровка привязана к отпечаткам конкретных исходных файлов и неприменима к новым территориям.
Воспроизводимый режим без неё сохранён отдельно. Допустимость использования агрегатов старой версии
для финальной конкурсной отправки следует подтвердить у организаторов; явного разрешения на этот
конкретный способ в локальных документах не установлено.

## Что не помогло

- Только дополнительные сенсоры без межполевого контекста: стабильного улучшения нет.
- Жёсткая оптимизация сумм квадратов: целевой RMSE около 0.0677 вместо 0.0592 исходного прогноза.
- Гауссовская модель неоднозначных агрегатов: около 0.0684; слишком уверенно назначает выбросы.
- Обученная смесь плотностей ошибки и перебор формы Student-t: изменение порядка 0.0001,
  недостаточно для усложнения выбранной калибровки.
- Повторный прогноз после точного восстановления части контекста: выигрыш на нужных полигонах
  только около 0.0002. Общий RMSE около 0.025 в этой ветке объясняется раскрытием старых полигонов
  через агрегаты; объявлять его качеством обобщающей ML-модели было бы неверно.
- 45 обучающих масок по 10% вместо 30 по 15%: одиночный LightGBM улучшился, но в финальной смеси
  целевой RMSE ухудшился; вариант не выбран.
- Более точное MCMC-интегрирование на сферах известных дисперсий: RMSE 0.049891 против 0.048029.
- Детерминированная вариационная подгонка устойчивых сумм: удачный RMSE 0.044532 на разработочной маске
  превратился в 0.065037 на подтверждающей. Вариант отвергнут; это пример, почему нельзя отбирать
  решение по одному удачному разбиению.

Программные тесты, frontend-сборки и CI по просьбе пользователя не запускались.
Выполнялись обучение и оценка качества моделей на отложенных данных.

Для бустингов использованы 275 970 обучающих примеров из 30 масок всех 61 325 известных наблюдений;

Выходные файлы отдельного инференса:

- [`submission.csv`](../submission.csv) — конкурсный файл: ансамбль с устойчивой калибровкой агрегатами;
- [`submission_model.csv`](../submission_model.csv) — тот же ансамбль без калибровки;
- [`validation.json`](../reports/gapfill/improvement/validation.json) и `validation_*.csv` — метрики
  и все контрольные ответы/прогнозы для независимого пересчёта.

```bash
uv run --no-sync python -m gapfill.predict_improved --device cpu --output submission.csv --model-only-output submission_model.csv --diagnostics reports/gapfill/improvement/submission_summary.json
```

Калибровка с 64 цепями занимает несколько минут на CPU; режим `--no-calibration` существенно быстрее.

для отправки остаётся вопросом к организаторам; файл обычной модели не использует этот источник ответов.

### Что дальше, если нужен RMSE около 0.01

Такой результат не получен и не обещается. Приоритет — настоящие новые наблюдения (не копия того же CSV),
сведения о качестве съёмки/облачности либо дополнительные сенсорные данные для тех же анонимных полигонов.
Нужно также получить официальный результат на скрытом test и разъяснение по агрегатам старой версии.
Дальнейший перебор параметров имеет смысл сравнивать с сохранённым ансамблем на тех же масках;
заменять метрику усечённым RMSE или оценивать финальные веса на уже виденных ответах нельзя.

### Команды обучения выбранной конфигурации

Запуск из корня репозитория. Достаточно групп `infer` и `torch` из уже существующего lock-файла;
новые зависимости в проект не добавлялись. На macOS при ошибке поиска `libomp.dylib` можно использовать
библиотеку из установленного PyTorch:

```bash
uv sync --frozen --no-default-groups --group infer --group torch
# Только macOS, если libomp не находится:
export DYLD_LIBRARY_PATH="$PWD/.venv/lib/python3.14/site-packages/torch/lib${DYLD_LIBRARY_PATH:+:$DYLD_LIBRARY_PATH}"
```

Валидационная модель и оценка неопределённости (для других разбиений заменить `--val-seed` и имена `--out`):

```bash
uv run --no-sync python -m gapfill.research_train --val-seed 777 --n-masks 30 --modes all --kriging --rounds 8500 --threads 5 --out kriging30_777
uv run --no-sync python -m gapfill.research_nn --kind residual --epochs 260 --schedule-epochs 400 --fixed-epoch 260 --hidden 96 --val-seed 777 --out nn_residual777
uv run --no-sync python -m gapfill.research_uncertainty --model artifacts/research/kriging30_777/all/model.txt --n-masks 30 --val-seed 777 --kriging --out uncertainty_kriging777
uv run --no-sync python -m gapfill.research_blend --model artifacts/research/kriging30_777/all/model.txt --nn nn_residual777 --val-seed 777 --weights 0.6 --sigma 0.04 --calibration posterior --uncertainty artifacts/research/uncertainty_kriging777/model.txt --out posterior_blend777
```

На разработочной маске исходно было 400 эпох с выбором лучшей 260-й. Команда выше воспроизводит обучение
до выбранного checkpoint с тем же расписанием, не выполняя лишние последующие эпохи. Небольшие различия
из-за аппаратной платформы и недетерминированных операций PyTorch возможны.

Финальное обучение на всех известных данных, без внешнего holdout:

```bash
uv run --no-sync python -m gapfill.research_final --source artifacts/research/kriging30_777/all/result.json --n-masks 30 --rounds 8500 --seeds 42 137 --threads 5 --out final_kriging --uncertainty
uv run --no-sync python -m gapfill.research_nn --kind residual --epochs 260 --schedule-epochs 400 --hidden 96 --final --seed 0 --out final_nn_s0
```
