# exp-100. Задача 2, шаг 0: как устроена норма организаторов (`ndvi_climatology_*`, `ndvi_zscore`, `status`)

Дата: 2026-09-05. Скрипт: `scratchpad/clim_reverse.py` (разовый).

Гипотеза: норма для точки (полигон, дата, год) = среднее **сырых** `primary_ndvi` того же полигона по **другим годам**
(train 2010–2024 + test 2025, поэтому `n_reference_years = 15`) в окне ±w дней по дню года; std — по тем же точкам.

| Окно w | LOO по году | R² по mean | RMSE mean | RMSE std |
|---|---|---|---|---|
| 0 | да | 0.675 | 0.087 | 0.068 |
| 3 | да | 0.967 | 0.028 | 0.021 |
| 5 | да | 0.986 | 0.018 | 0.014 |
| **7** | **да** | **0.996** | **0.0095** | **0.0090** |
| 10 | да | 0.996 | 0.0092 | 0.0068 |
| 15 | да | 0.991 | 0.015 | 0.013 |
| 7 | нет | 0.991 | 0.015 | 0.011 |

Уточнение ширины окна (4 000 точек): w=7 → RMSE 0.0105, **w=8 → 0.0036 и 40 % точек совпадают точно**, w=9 → 0.0074.
Без исключения текущего года всегда хуже → норма считается leave-one-year-out, окно **±8 дней по дню года**,
std с ddof=0 (0.0021 против 0.0024). Остаток объясняется 15 % скрытых точек test в 2025 году, который входит
в референс для train-полигонов.

Следствия:
1. `status` организаторов воспроизводим для любого полигона с историей — и для test, и для новых территорий в сервисе.
2. Норма считается по сырым значениям смеси сенсоров, поэтому Z-score смещён по сенсору (S2 −0.23, MODIS +0.52 из EDA):
   для честной детекции норму и наблюдения надо гармонизировать (шкала S2), что в exp-101.
